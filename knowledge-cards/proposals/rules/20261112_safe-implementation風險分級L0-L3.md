風險等級判定（先於任何修改；「風險等級」只管寫程式的風險，和 miko-core §1「0. 分級（輕量／完整）」是兩套，互不取代；等級與一句理由寫在對齊行之後，不佔對齊行，miko-core §1 第 4 點規定第一則回覆第一行是對齊行）：

   - L0（文件錯字、註解、格式、不改行為的重命名）：直接做；檢查 diff 與基本靜態檢查。
   - L1（單一功能、測試、局部修補、讀取來源的資料處理）：照下方第 1～8 步；方案寫一兩句即可；跑相稱的測試。
   - L2（設定、共用介面、資料或儲存結構、CI 或 workflow、Skill 或正本、會寫入雲端或 GitHub 的動作）：先列影響範圍、相容性與回復方式（miko-core §2.3 BLOCKED 句）；Skill 與正本走獨立稽核；寫入一律分支加 PR，不直推 main。
   - L3（不可逆或對外：推送 main、合併、發送、部署、費用、權限變更）：停在可逆的準備完成狀態；寫出精確內容（diff 或檔名）、回復方式，等 MIKO 當次明確批准（引用該則訊息）；常設授權不算（README 跨平台寫入須當次明確授權）。刪除不走這條批准路徑：一律改搬 _to_delete/，當次指示也不改成永久刪除，永久刪除由 MIKO 自己操作（miko-core §7）。
   - 唯讀請求（只讀取、分析，不改任何檔案或設定）：不套 L0～L3，維持 safe-implementation 預設「只分析」；一旦要寫入才判等級。
   - 判定規則：同一任務含不同等級，取最高；觸及認證、付款、個資、刪除（搬 _to_delete/ 算 L2）、公開發布至少 L2；不可逆、對外發送、改真實資料、影響其他人視為 L3；拿不準時往高一級。
