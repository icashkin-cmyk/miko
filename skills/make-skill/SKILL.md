## 1. 問問題
- 必問：這次的成果哪一份是 MIKO 接受的（檔名或訊息）；要做成新 Skill 還是併入哪個既有 Skill。這兩題由 S1、S3 執行，答不出來照兩步的失敗處理。
- 預設值：MIKO 沒指定時，先判能不能併入既有 Skill（優先併入，避免功能重複）；做出來的一律是草稿，MIKO 確認前不推正本。
- 非總召的聊天室：做到 S8 為止，打包成提案交總召（miko-core §6 提案流轉），不寫正本；S9～S11 由總召做。

## 2. 解決（有先後依賴，依序做）
- 站點閘門（MIKO 2026-11-08 12:38）：每一步是一個站點，照這個順序走：做完 → 用該列「驗收證據」查驗 → 看要不要加強（有就補完再查驗一次）→ 通過才存檔（草稿階段存工作目錄或專案檔並記檔名；正本只在 S9 推）→ 才做下一站。沒通過照「失敗處理」欄，不跳站。被做成的 Skill 也照這個方式寫：每一步都寫通過條件，例如美食「查地點通過 → 店家核驗通過 → 查評價通過 → 才輸出」。

## 3. 後設（常見錯）
- 只改成六欄就以為可執行：六欄仍是文字，能算的步驟沒交給程式，每個對話做出來還是不一樣（例：照片 Skill 的材料表比對程式寫好了卻沒接進流程，交給模型手填）。
- 成果還沒被 MIKO 接受就做成 Skill，把錯的做法固定下來。
- 沒和現有規則比對就新增，造成重複或衝突；新規則疊在舊規則後面，新舊並存，模型讀到哪句照哪句。改版要把被取代的句子移進刪除清單或明確標「已取代」並移出流程節。
- 範例數字和真實資料一樣，被當成真值照抄。
- 檢查程式只檢查檔案齊不齊，不檢查內容是否照規則產生；lint 只檢查格式，PASS 不代表可執行，標型對不對最後要稽核看。
- 全 repo 測試順帶跑了被暫停任務的程式：實跑前先看測試會呼叫什麼（例：check_repo C6、C9 會跑 bt_min.py 回測引擎樣本，先確認它落在 S9 例外才照跑，1.2.51 起；原句見刪除清單 v0.4；只檢查 Skill 改版時用 `--only C11`）。
- 自己做、自己驗：放行前用 independent-audit 冷啟動稽核。
