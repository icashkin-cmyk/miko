# dghp-travel v0.8-cumulative-candidate｜旅遊與行程規劃｜MIKO candidate

## 0. 責任、資料、工具、輸出與授權

- 負責什麼：只負責旅遊行程、交通、景點、住宿、返程閉環與現場備案；一個 Skill 不代替 dghp-food 的餐飲品質判定。
- 看哪些資料：使用者本輪輸入、專案內已授權的旅遊資料、官方天氣／景點／交通／住宿來源、Google 地點資料與程式輸出。
- 接哪些連接器：程式執行、Google 地點搜尋／地圖、官方網站或官方社群、天氣查詢與 tw-alert-check；沒有實測證據不得宣稱工具已啟用。

- 交回什麼：分流結果、需求摘要、來源與查核時間、時間軸、硬截止、返程、主／備方案、READY_TO_GO／NEEDS_FINAL_CHECK／DO_NOT_EXECUTE 判定。

## 0.1 累積式升級與歷史版本保護路由

- 本 Skill 的任何升級、優化、重構、修正、移轉、取代或廢止，必須先載入 `version-evolution-preservation`。
- 升級前保存目前 `SKILL.md`、版本、來源、日期、Commit 與 SHA-256；舊版保存於 `archive/dghp-travel/<version>/`，不得由新候選覆蓋。
- 修改採累積式演進，逐項標記為：繼承、強化、新增、修正、重構、廢止。未理解或未驗證的內容保留並標記 `UNKNOWN`。
- 每次候選升級必須保存 `diff`、修改理由、影響、回復目標與新 SHA-256，並分開記錄候選、目前使用、正式採用、歷史版本與 Runtime 狀態。
- 升級後必須重跑原有 mapping、正向、負向、邊界、異常、回歸、Mutation 與獨立驗收；格式通過不等於升級完成。
- 任一測試為 `FAIL`、`NOT_RUN`、`UNKNOWN` 或 `BLOCKED` 時，不得標記 `QUALIFIED_FOR_NEXT_STAGE`；修正只能發生在新候選，不能修改歷史快照。
- 未經明確授權不得刪除、覆寫、廢止既有規則或宣稱 GitHub／Runtime 已生效。

### 工具與程式要求

- 若使用 `itinerary_check.py` 或 `food_pool.py`，必須先取得指定版本與測試結果；工具失敗時回到本 Skill 的人工流程並說明原因，不重寫程式冒充通過。
- 程式輸出 `EXECUTABLE`、`INCOMPLETE_UNVERIFIED`、`NOT_EXECUTABLE` 與人工判斷不同時，兩者都要保留並說明差異。
- 已核班次必須有官方網址與查核日期；回程最後一段必須抵達 `home`；大眾運輸必須保留進站、步行、購票、候車與轉乘緩衝。

## 3. 後設

- 路線已規劃不等於可執行；查到時刻表不等於指定日期已核實；現在營業不等於抵達時營業；找到旅館不等於有空房；Google 星等不等於目前餐飲品質。
- `UNKNOWN` 不等於 0、False 或 PASS；成本未知不得填 0。
- 景點必須依目標日期、抵達時間、指定日公告與最後入場判定。
- 估算移動時間必須標「估算，非導航」；同名分館必須核對地址。
- 出發前狀態變化時必須重驗。
- 出發前若天氣、班次、營業、封閉或住宿狀態變化，必須重新驗證；不得沿用過期的 READY_TO_GO。
- 寵物只有在明確同行時才啟動檢查，且必須重驗當日狀態。
- 所有高風險或不可逆的預約、付款、對外聯絡都必須由使用者明確授權並親自完成。

## 4. 檢查

### 驗收條件

- expected：指定日期、指定地點、返程與來源均可追溯時，輸出完整時間軸與三態判定。
- forbidden：缺返程、把 UNKNOWN 當 PASS、把他日班次當指定日班次時不得輸出 READY_TO_GO。
- 相近反例：有完整景點週表但沒有指定日公告；有直線距離但沒有導航；有去程班次但沒有回程。這些都不該觸發 READY_TO_GO。

- AC-T1：時間軸閉環回到起點，且早於最晚回家時間。
- AC-T2：每個節點都有週表與指定日狀態；未核到標 `UNKNOWN`。
- AC-T3：天氣與班次有官方來源或 `NOT_RETRIEVED`。
- AC-T4：估算移動時間標示「估算，非導航」。
- AC-T5：輸出 `READY_TO_GO`／`NEEDS_FINAL_CHECK`／`DO_NOT_EXECUTE`、原因與查核時間。
- AC-T6：每個 T1～T6 均有輸入、輸出、禁止事項、證據與失敗處理；前一步未通過不得跳到後一步。

### 實跑題與通過條件

實跑題：指定日期 14:00 從住家出發，使用者指定交通方式前往兩個市區景點，18:00 前回家，並要求其中一餐交由 dghp-food。

通過條件：

1. T1 正確分流並取得日期、起點、景點、交通與最晚回家時間。
2. T2 保存天氣來源或標 `NOT_RETRIEVED`。
3. T3 每個景點都有地址、指定日狀態、最後入場與查核時間。
4. T4 只使用指定日期班次；估算移動標示「估算，非導航」；時間軸回到起點。
5. T5 保留 dghp-food 品質結論，不自行改寫，並提供至少一個可回接返程的備案。
6. T6 依證據輸出三態之一；若天氣、景點本體或班次未核實，不得輸出 `READY_TO_GO`。
7. 所有測試結果、來源、命令、stdout、stderr、Exit Code 與 Hash 保存於候選 evidence；本 Skill 不宣稱 GitHub 或 Runtime 已啟用。
