## 2. API_REVIEW_REQUIRED

**API_REVIEW_REQUIRED：YES**

### 2.1 何時必須呼叫 Claude API

下列任一情況發生，**必須**實際呼叫 Claude API 取得審查回覆，不得以 Manus 自行判斷、Gemini 意見或舊審查替代：

1. 任一份候選文件內容有「改變意思」的修訂（對應 17:41 規則的反面，見 §5）。
2. 涉及邊界、授權、停止狀態、硬禁止、ADR 引用的任何修訂。
3. 送出「治理審閱」或「採用」申請之前。
4. 材料 SHA-256 與上一次已審版本不同，且差異不能被機械證明為純格式。
5. 出現 `CONFLICT`、或 Manus 與其他審查者意見不同。

純錯字、標點、排版（機械可證）**不需**重新呼叫，但須記錄 diff 與判斷依據。

### 2.2 每次呼叫必須保存

| 欄位 | 內容 |
|---|---|
| `request_id` | 本專案自訂唯一編號 |
| `request_payload` | 完整送出的提示與材料（或其不可逆雜湊＋原文存放位置） |
| `response_payload` | 完整回覆原文，不得摘要取代 |
| `model` | API 回報的模型識別字串（原樣保存，不自行改寫） |
| `request_time` / `response_time` | Asia/Taipei，含時區 |
| `material_sha256` | 每份送審材料各自的 SHA-256，及固定 commit |
| `http_status` / `error` | 成功與失敗都要記 |
| `api_call_status` | 見 2.3 |

### 2.3 API 失敗時的標示

| 情況 | 標示 | 規則 |
|---|---|---|
| 呼叫失敗、逾時、被截斷 | `API_CALL_FAILED` + `REVIEW=NOT_RUN` | 不得改寫成 PASS／REVISE |
| 只收到送出確認、無審查內容 | `ACK_ONLY` + `REVIEW=NOT_RUN` | **ACK 不是審查完成** |
| 回覆內容不完整、未逐項裁決 | `REVIEW=INCOMPLETE` | 須補問 |
| 回覆未引用材料 SHA | `REVIEW=UNBOUND` | 無法確認審了哪個版本，視為無效 |
| 重試 | 每次重試是新的請求，各自保存 | 不得覆寫失敗紀錄 |

失敗時唯一允許的結論是「**審查未完成**」，並列困難卡；不得以「已嘗試呼叫」當作已審。
