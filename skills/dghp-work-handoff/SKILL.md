# 可恢復工作交接 v1.0（dghp-work-handoff）｜2026-11-10

> 名詞（1.2.53，ADR-076）：本檔短名詞第一次出現在這一行，寫成「短名（正式名稱）【類型】」；每個名詞的定義、觸發條件、執行動作、輸出格式、完成判準、失敗處理、不適用情況、相關名詞見 MIKO 核心詞彙與行為定義表（skills/miko-core/references/term-definitions.md，https://raw.githubusercontent.com/icashkin-cmyk/miko/main/skills/miko-core/references/term-definitions.md）。正本（正式名稱：GitHub 上的正式規則來源與目前採用版本）【限制】；任務四態（正式名稱：交付結果四種狀態判定：完成／完成但有疑慮／需要資料／卡住）【輸出】；治理（正式名稱：規則版本、變更、授權、審查與正式放行管理）【流程】。

## 原則
交接紀錄是工作索引，不取代完整來源或 Canonical。只在授權可寫目錄保存；READ_ONLY 時在回覆交付，不創建檔案。保存後才可說已保存；無可用排程／持久化工具不承諾背景追蹤。

## 交接欄位
TASK_ID、PROJECT_ID／領域、目標、授權及禁止項、來源檔／版本／位置、當前程式與資料位置、已完成且有證據的工作、執行命令／結果、已知失敗與重現方式、UNKNOWN／CONFLICT、尚未完成、下一個可執行步驟、輸入依賴、恢復入口、最近實際更新時間。

## 執行
將完成、待驗證、阻塞、被拒絕與未授權分開。更新時只修改本任務狀態，不混入其他市場、健康、財務或案件動態。保留導致重大決策的證據和例外，不僅留下結論。
長任務在里程碑提供短進度與已知成果；避免反覆「開始、繼續處理」但沒有結果。收到更正時先納入新要求，保留仍有效成果與需重驗部分。
恢復任務先核對文件／檔案仍可讀及版本一致，時效性資料重新確認。不要從舊摘要推定今天的帳戶、價格、權限或 Runtime 狀態。
多個 AI 或多房同時做同一專案時：共用介面（CSV 欄位、API、狀態碼、檔名規則）要改，先寫進交接檔「介面異動」一節再改，接手方先讀這一節。接手以專案狀態（任務、commit SHA、測試結果、下一步）為準，不以聊天紀錄為準。（2026-10-24 增補，H-03）
轉交給其他房間、平台或 AI 時原文照轉，不改寫、不摘要；自己的補充另起一段並標明是補充。（2026-10-26 增補，ADR-016）

## 驗收
另一工作階段能從交接中的實際入口辨識範圍、已完成證據、剩餘工作和禁止項。未執行不填已完成；無檔案存取就提供可貼用交接文本並標示尚未持久化。
讀者測試（1.2.64，ADR-087；MIKO 2026-11-10 回「加」，來自總召專案 Doc Co-authoring 評估）：交接檔要存檔或交給接手方之前，先寫出接手者最可能問的 3～5 個問題（例：現在做到哪、下一步是什麼、哪些不能做、證據在哪）；把交接檔交給沒看過本對話的子代理或新對話，只憑交接檔回答；答錯或答不出的題，補交接檔對應的欄位後再測一次，全部答對才算通過。測題、作答與判定寫在交接檔最後一節；環境沒有子代理也不能開新對話，或額度將盡跑不完時，標 NOT_RUN 並寫原因（額度將盡時先存交接檔，讀者測試留給接手的新對話第一步跑），不宣稱通過。只說「收工」、本對話沒有工作也沒有交接檔時，不跑讀者測試，照 description 回覆交接欄位、存檔處與任務四態即可。

## Claude 環境對應（claude.ai 改編，2026-10-13）
- 有檔案工具時：交接寫成 UTF-8 Markdown 檔（短檔名），以 SendUserFile 交付，回覆只放一行說明。狀態分開回報：已寫本地／已交付 MIKO／已存遠端（Drive、GitHub）／已讀回／內容一致（有雜湊才算）；沒做到的寫 NOT_DONE 或 UNKNOWN，不混成一個「已保存」。（2026-10-26 增補，H-06）
- 無檔案工具或使用者只要文本：交付單一可貼用 Markdown Code Block，標 `PERSISTED=NO`。
- 交接中的程式碼狀態以 GitHub 固定 commit／branch 指向，不貼整檔；Notion 狀態以頁面連結指向，不複製內容。
- 遮蔽 Token、帳密、API Key 與個資；不寫入私密推理。

## 收工（miko-core §1.1 觸發；2026-10-23 增補）
1. 依上方交接欄位寫交接檔（UTF-8 Markdown，實際交付後才說已保存）；交給其他 AI 或另一個 Claude 對話做正式交接時改用 19 欄 FINAL_HANDOFF（原寫「外部 ChatGPT 或 Codex」，兩者 2026-11-02 起停用，ADR-039）（multi-agent-coordination-engine §7.8）。
2. 列出待推送 GitHub、待同步 Notion 的項目；這些跨平台寫入只在當次授權後執行，寫入前後讀回。Drive「MIKO_ARCHIVE」依下節的常設授權；GitHub 正本 repo icashkin-cmyk/miko 依 ADR-016 常設授權（只更新 MIKO 正本，推送後讀回）；同 repo 的 sync/ 依 ADR-020（只寫 Claude 自己的同步檔）。
3. 跨專案、會再遇到的坑（不是單一任務的狀態）列為「踩坑候選」一到三行，由 MIKO 決定是否存入記憶或 Notion；不另建帳本。
4. 以 miko-core §5 第 8 項的任務四態收尾。額度重置後的下一則對話，從交接檔的「下一個可執行步驟」續做；不能假設平台會在額度重置時自動續做，沒有實際排程或系統續跑紀錄不得宣稱已在背景執行，續做前先讀最新狀態，不把舊 BLOCKED 當已解除，不為續做新增定時排程（細則見 miko-core §1.1，ADR-055）。
5. 本對話沒有工作時（例如新對話只說「收工」），也要在回覆列出交接欄位清單（沒有內容的欄位寫 NONE）、存檔處（Drive MIKO_ARCHIVE，本次不建檔的理由）與任務四態（沒有本輪工具輸出不得標「完成」；從 miko-core §5 第 8 項四態選適用的一個並寫理由，通常是「需要資料」：本對話沒有可交接的任務）；只是不建交接檔，不得只回「沒有可交接的工作」（ADR-045）。

## Drive 存檔（ADR-012；2026-10-23 增補）
1. 觸發：依 miko-core §1.1（收工、可驗收階段完成、額度將盡，或 Type B／治理工作收尾且本輪改了狀態、決策或正本）。單一問答不存。
2. 先更新該領域狀態檔與 HANDOFF（現況、待決、未完成待辦、最小下一步）。
3. 寫入 Google Drive「MIKO_ARCHIVE」下的子資料夾「YYYYMMDD_領域_版本」：只新增；不覆寫、不刪除、不移動、不分享、不改權限。授權只限這個資料夾，其他跨平台寫入仍須當次授權（GitHub 正本 repo icashkin-cmyk/miko 例外，見 miko-core §7）。
4. 存什麼：狀態檔、決策紀錄、HANDOFF、當輪正本。Claude 帳號已存的 Skill 不重複上傳全文；程式碼以 GitHub 為權威。大檔（約 50 KB 以上）不經對話以 base64 上傳，改請 MIKO 手動拖入，並在回覆寫明未存項目。
5. 讀回：依新檔 ID 讀回內容，和本機內容比對 SHA-256（不符標不一致、回報阻塞，不覆寫）；只讀得到檔名與大小時，內容一致性標 UNKNOWN（內容未驗證），不寫已驗證。
6. 回報：存了什麼、位置、讀回結果、未存項目與原因。寫入失敗或連接器不可用時回報阻塞與檔案所在處，不換其他平台代存。

## 派工（給其他 AI 或另一個 Claude 對話；2026-10-26 增補，ADR-016；原寫「給 Codex」，Codex 自 2026-11-02 停用，ADR-039）
1. 一次給齊：目標、相關檔案路徑（repo、分支、資料夾）、完成條件（可判定的驗收）、禁止事項與授權範圍。
2. 預設附上：「不要推送，只存本地；不發文、不發訊息」。MIKO 說「推」才推送、合併、部署。
3. 要求對方回報：改了哪些檔、去哪裡看、怎麼驗過、哪些沒做完與卡點；回報原文照轉回治理房。
4. 派工內容需要交接時，用上方交接欄位；交給其他 AI 或另一個 Claude 對話的正式交接用 19 欄 FINAL_HANDOFF。
