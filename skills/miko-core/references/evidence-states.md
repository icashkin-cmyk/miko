- 證據與狀態（ADR-040，2026-11-04 GPT 記憶匯入去重後新增）：
  - 狀態分層，不得互相代替：來源存在／全文已讀／已安裝／已載入／行為測試通過／實際生效；送出／收到／接手／完成。狀態不明先讀回，不盲目重送。（擴充上方「Skill 取用」的「安裝、讀取、執行、驗證分開回報」，兩條同義處以本條為準。）
  - 指令狀態六層（ADR-058；MIKO 2026-11-08 指示）：指令（規則、Skill、帳號偏好、自訂指令、派工）的狀態分六層，不得互相代替：已保存（寫進檔案、repo 或 Drive，有路徑、commit 或檔案 ID）／已送達（交到目標平台或對象，例如推上 main、MIKO 貼進帳號設定）／已被接收（目標端回報收到，例如新對話對齊行照抄到新版本號；依 §1 第 5 點，這不證明讀過全文）／已執行（目標端照做一次，有輸出）／已驗證（獨立重跑或回歸測題 PASS，有逐題紀錄）／已在 Runtime 生效（在實際使用的平台與模型、新對話自然觸發下行為符合，對應 §0 ⑤「已載入」）。每層要有本輪或可回指的證據，沒有證據的層標 UNKNOWN 或 NOT_RUN；前一層成立不代表後一層成立，例如推上 main 只到已送達，對齊行只到已被接收（§1 第 5 點）。本條的「指令」指整份規則、Skill、偏好或派工，§2.4「指令條目」指 Skill 內的單一條目。指令的狀態回報用本條六層；上一條「送出／收到／接手／完成」仍用於派工與交付物；和上一條「來源存在／全文已讀／已安裝／已載入／行為測試通過／實際生效」的對應：已被接收不等於全文已讀，已驗證約等於行為測試通過，已在 Runtime 生效約等於實際生效，兩套同時出現時指令以本條為準。回報指令狀態時（交付、收工、測題都算），六層名稱逐層寫出，每層標一個結果：是（附證據）／否（做了且確知失敗，寫明確狀態並附證據，例如 FAIL、BLOCKED、CONFLICT）／NOT_RUN（本輪沒做，寫原因）／UNKNOWN（做了但查不到結果）；確知失敗的層不得標 UNKNOWN；不得只用「沒寫檔」「沒推送」「未採用」概括帶過，也不得省略後面幾層。本句只規範回報格式，不新增回報義務；沒有指令狀態要回報的回覆不適用（ADR-059；MIKO 2026-11-08 原話「回報 不然一堆查不到也不能」）。
  - 稽核文件要逐段讀完正文、表格、附錄、例外與否定條件；沒讀完不得稱「已稽核」，要交代分母、未讀範圍、讀取失敗與截斷。
  - 自測與獨立重跑分開記錄；保留舊版、原始 FAIL、反例，不覆寫歷史證據。
  - 已接受的規則凍結；新想法先寫成候選或 A／B／C 方案，經 MIKO 依證據選定才換版。
  - 評估閘門時同時看風險與機會：不把取證方法自動變成硬性關卡，UNKNOWN 依 §7 不當通過；記錄風險降低多少、移除的後果、最低必要證據、低成本替代方案。
  - 完整交付或封存：ZIP 加說明 Markdown、逐檔清單（含雜湊）、排除清單、驗收紀錄、恢復方式；本機保存、外部送達、外部封存、讀回相符依上方「狀態分層」分開記錄（讀回比對依 §7 用 SHA-256）。
  - 機器評分或固定格式作答：保留指定的程式碼區塊、欄位名稱、型別與順序，不用解說取代機器可讀答案。

- 1.2.64 新增（ADR-087，R5 審查 F、G 項；接在上方「狀態分層」那一條之後讀）：
  - 遠端狀態未知（例如推送、合併、Drive 寫入送出後沒拿到結果，不知道有沒有成功）：先唯讀查詢目前狀態（例如讀 main 的 commit、讀 PR 狀態、依檔名或 ID 搜 Drive）；要恢復時由原 writer 做，不由另一工作串重做，避免重複寫入或互相覆蓋。
  - STALE（證據過期）：證據上的版本或 commit 已不是本輪實際讀到的（例如長串中途重讀 VERSION 發現已升版〔miko-core §1 第 3 點，ADR-064〕、工作串回報的 commit 和目前 main 不符）時，該證據標 STALE，不得當決策依據；重讀或重跑取得新證據後才用。STALE 不等於 FAIL，也不等於 PASS。
  - 別人讀到的不算自己讀到（R5-C07）：其他工作串、平台或 AI 回報的「已讀、已跑、已推」，寫成「某某回報」並附四項：哪一串或哪個平台、來源（檔名或網址）、讀取或執行時間、版本或 commit；自己這一層沒讀到的照 §7 標 NOT_READ，不改寫成自己已讀或已驗證（上方「狀態分層」：送出／收到／接手／完成不得互相代替）。回報的版本或 commit 和本輪讀到的不同時照上一條標 STALE。
  - 採納說明：本節前三條（F 遠端狀態未知、G STALE、R5-C07 別人讀到的不算自己讀到）在 R5 審查時列為候選，總召 2026-11-10 依 MIKO 11-08 20:06 授權選定併入 1.2.64（上方「已接受的規則凍結；新想法先寫成候選」照常，本節即候選選定後的換版）。
