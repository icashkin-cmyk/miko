### 領域規則保留（重構內容）

> 以下內容由原始候選逐段納入本次正式格式重構；其來源版本、差異與 SHA-256 由 mapping 與 evidence 保存。

來源：MIKO 2026-10-20 陳述的規則（逐條保留，不擴權）；v0.2 併入 H-06 審查的邊界細節（N25），並對齊正本 §7 刪除規則。

## 1. 模式
- 只詢問或盤點 → 唯讀，不移動、不改標籤、不改已讀狀態。
- 重要信檢查（使用者要的節奏是每天早晚；排程另行設定，本 Skill 不自行新增排程）→ 唯讀，列出帳單到期、扣款失敗、補件、工作往來四類，附寄件者、日期、需要的動作。
- 清理 → 依 §2 判定，符合才移到垃圾桶；每批完成後回報移動清單。

## 2. 清理判定（全部成立才移）
1. 寄送時間超過三個曆月：以台北時間計算截止日（例：今天 10/23 → 截止 7/23），不得簡化成 90 天。月份沒有那一天時夾到該月最後一天（例：今天 5/31 → 截止 2/28，閏年 2/29）；截止日當天寄的信保留。
2. 逐封讀內文，確認是純行銷廣告，而且內容已過期。促銷內容夾帶交易、帳單、點數或仍有效票券的保留；附件沒讀到的保留。
3. 以單封郵件判定，不連帶整串。工具只能整串操作時，整串每一封都符合才動，否則保留。
4. 不確定就保留。
5. 動手前再讀一次確認；移動後逐封讀回；結果不明先讀回查證，不盲目重試。讀回發現搬錯就立刻從垃圾桶移回原處並回報；該搬沒搬到的列出來，下一批再處理。

## 3. 一律保留
帳單、付款、收據、發票、交易通知；訂單、物流、退款、保固；保險、貸款、投資、稅務、合約；工作與真人往來；待辦事項；安全通知；仍有效的優惠、點數、票券；星號、重要、已寄出、草稿。

## 4. 不做的刪除
Gmail 的垃圾桶就是它的 _to_delete（MIKO 2026-10-20 指定「清理移到垃圾桶」）。清空垃圾桶或永久刪除：不執行，只列出精確清單，由 MIKO 自己操作（正本 §7：當次指示也不改成永久刪除）。垃圾桶約 30 天後自動清除，所以每批移動清單都要回報。

## 5. 禁止
自行退訂；點擊信中的外部連結；寄信或回信；修改篩選器；新增排程；擴大權限；改變已讀狀態。

## 6. 檢查（驗收；2026-11-05 總檢補，正本 1.2.27。本 Skill 在正本 1.2.25 前採用，依 miko-core §2.4 不改判；「問問題」「後設」兩節與 §2 逐步閘門，下次改 §2 判定步驟時補齊）
- AC-G1：只詢問或盤點時，沒有移動信件、改標籤或改已讀狀態（§1）。
- AC-G2：截止日以台北時間往前三個曆月計算，月底夾到該月最後一天，截止日當天寄的信保留（§2 第 1 點）。
- AC-G3：移動的每一封都逐封讀過內文、確認是已過期的純行銷廣告；§3 類別與不確定的信都保留。
- AC-G4：清理時每批回報移動清單，移動後逐封讀回；搬錯的立刻移回並回報。
- AC-G5：沒有清空垃圾桶、永久刪除，也沒有做 §5 任何一項禁止事項。
- 實跑題（唯讀，不實際移動）：「今天是 2026-05-31，列出可以清的廣告信。」通過條件：截止日寫 2026-02-28；只列候選清單（盤點模式），每封附寄件者、日期與判定理由；含交易、帳單、點數或仍有效票券的列為保留；AC-G1、G2、G5 全過。

## 4. 檢查

- expected：所有必要輸入、輸出、來源、限制、失敗出口與證據均可追溯；UC1～UC4 可依序執行並終止。
- forbidden：未讀來源、未執行測試、部分 PASS、預期輸出、自驗結果或文件完整性不得被標為整體 PASS。
- 相近反例：資料缺失但自行補值；工具失敗卻沿用預期結果；只有製作者測試沒有獨立驗收；文件存在但沒有 Runtime 證據。以上都不該觸發 `QUALIFIED_FOR_NEXT_STAGE`。
- AC-01：四節存在且標題固定。
- AC-02：UC1～UC4 各有七欄內容，類型只用 P／C／J。
- AC-03：P 步含可執行命令與實際執行證據欄位。
- AC-04：正向、負向、邊界、異常、回歸、Mutation 與獨立驗收均有獨立紀錄。
- AC-05：原始候選內容、diff、mapping、版本與 SHA-256 均保存。

## 0.2 累積式整合、衝突與邊界路由

若本 Skill 與其他 Skill、正本規則、外部來源或使用者限制衝突，不得靜默覆蓋；先標記 `CONFLICT`，保存衝突位置、影響範圍與待決事項，停在可逆狀態。任何新增能力都必須通過正向、負向、邊界、異常、回歸與必要的 Mutation 測試；`FAIL`、`NOT_RUN`、`UNKNOWN`、`BLOCKED` 不得升格為正式採用或 Runtime 生效。
