## 1. 目標與非目標

目標
1. 讓 Manus 在 knowledge-cards/ 工作時，能把「草稿生成、整理、改寫、初步檢查」交給 Claude，減少 MIKO 在兩個平台間搬運文字。
2. 呼叫的輸出一律當「提案草稿」，沿用現行 PR 審查鏈，不新增繞過審查的路徑。
3. 成本可控（模型分級、用量上限）、金鑰不進版控。

非目標
1. 不讓 Manus 取得審查、放行、改版本號、直推 main 的權限（雙總召試行邊界不變，ADR-088）。
2. 不讓 Claude 輸出直接寫入 skills/、.github/、tests/、VERSION、sync/。
3. 不做下單、交易、Broker、LIVE，也不經此路徑繞道（硬禁止，當次指示也不做；繞道路徑亦同，§7 (5)）；台指期維持停止。
4. 不做「Claude 與 Manus 自動多輪互相對話」的迴圈。
5. 不取代獨立稽核：Claude 呼叫 Claude 不算獨立驗證。

## 2. 架構

```
Manus（knowledge-cards/ 總召）
  │  HTTPS POST /v1/messages（金鑰由 Manus 平台密鑰設定注入）
  ▼
Anthropic Messages API（Claude）
  │  回傳文字
  ▼
Manus 把回傳存成 proposals/<類型>/YYYYMMDD_主題.md（首行「未驗收提案」）
  │  分支 + PR
  ▼
Claude 治理總召審查 → MIKO 逐件批准 → 才可能併入
```

模型分級（照 ADR-035 / ADR-091 的輕重量分級，具體模型代號為本草稿建議，採用前須查官方模型清單）

| 用途 | 建議模型 | 思考程度 |
|---|---|---|
| 輕量：改錯字、格式整理、摘要、翻譯、照規則填欄位 | claude-haiku-5-5 | 低 |
| 重量：提案草稿、整合比對、規則文字改寫 | claude-sonnet-5-5 | 中 |
| 最困難、無標準答案的判斷、提案的冷啟動反方檢查 | claude-fable-5-2 | 高 |

claude-opus-5-5 用於改正本與放行，這兩件 Manus 不做，所以 Manus 呼叫清單不含 Opus。

呼叫約束（建議）
- 每次呼叫帶明確 system 提示：角色是「提案草稿助手」，不得宣稱已審查、已放行；輸出首行固定「未驗收提案」。
- 單次呼叫設 max_tokens 上限；不開自動重試迴圈（失敗最多重試 1 次，仍失敗走困難卡）。
- 輸入只放公開 repo 內容；不送金鑰、個資、工程或單位名稱。
- 每次呼叫在提案檔尾記錄：模型代號、呼叫日期、輸入檔名與 SHA-256、輸出 SHA-256（可追溯，No Silent Supersession）。

## 3. 金鑰處理

1. 金鑰只由 MIKO 自己填到 Manus 平台的密鑰設定；不在對話中貼、不寫進 repo、提案檔、PR、交接檔或日誌。
2. 專用金鑰：只給此用途，不與其他用途共用；在 Anthropic 主控台設用量／支出上限，上限值由 MIKO 決定（UNKNOWN）。
3. 外洩處置：任何疑似外洩（出現在 repo、PR、日誌、對話）一律立刻作廢重發；Claude 端不複述、不引用金鑰任何片段。
4. 範例與測例中金鑰位置只寫 <KEY>。
5. Claude 側工作區（雲端）不寫任何金鑰檔案；本草稿不產生也不需要金鑰。

## 4. 與現行治理的邊界

| 項目 | 邊界 |
|---|---|
| Manus 權限 | 只管 knowledge-cards/；只開分支與 PR；不直推 main、不審查、不放行、不改版本號（ADR-088） |
| 呼叫輸出的地位 | 只算提案草稿，首行「未驗收提案」；不是規則、不是審查結果 |
| 審查 | 由 Claude 治理總召審查；規則或 Skill 修改須獨立稽核，不自審 |
| 併入 | 搬入 skills/、.github/、tests/、VERSION、sync/ 須 MIKO 逐件、當次明確批准；常設免問推送授權不算 |
| 衝突 | 卡片與正本衝突以正本為準 |
| 停止 | MIKO 說停止即恢復 Claude 單一總召，此呼叫通道同時停用 |

## 5. 風險與反證

| 風險 | 影響 | 緩解 | 殘餘 |
|---|---|---|---|
| 金鑰外洩 | 被盜用、費用失控 | 專用金鑰、支出上限、只放平台密鑰設定 | 平台自身安全無法由本 repo 驗證（UNKNOWN） |
| 費用失控 | 自動呼叫放量 | 模型分級、max_tokens、不開迴圈、上限 | 上限設定是否生效須實測 |
| 同源偏誤 | Claude 草稿再由 Claude 審查，錯誤可能一起放行 | 規則／Skill 修改仍走獨立稽核（冷啟動子代理或換模型） | 非規則類文件仍有同源風險 |
| 繞過審查 | 輸出被當正式內容 | 首行標記、只落 proposals/、PR 由總召審 | 靠流程紀律，無技術強制（可另提 CI 檢查提案） |
| 資料外送 | 內容送往 API 供應商 | 只送公開 repo 內容 | 供應商資料保留政策須讀官方條款（NOT_READ） |
| 責任模糊 | 草稿來源不明 | 尾註記錄模型、日期、SHA-256 | 無 |
| 繞道硬禁止 | 經此通道請 Claude 產生下單腳本 | 輸入清單排除交易、Broker 類任務；§7 (5) 繞道亦禁止 | 靠人工與審查 |

反證與待證：本方案假設「搬運成本」是主要痛點。反證條件：若 3 個月內 Manus 草稿多數仍需 Claude 總召整份重寫，則呼叫通道沒有節省工作，應停用。目前沒有搬運次數或成本的實際資料（UNKNOWN）。

## 6. 替代方案

| 方案 | 說明 | 優點 | 缺點 |
|---|---|---|---|
| A. 現狀（人工搬運） | MIKO 在兩平台間貼 PR 連結與結論 | 零新增風險、零金鑰 | MIKO 負擔高 |
| B. 只讓 Manus 讀 GitHub 正本，不給 API（推薦的最小起點） | Manus 讀正本與提案，開 PR；Claude 總召在 PR 審查 | 無金鑰、無費用、邊界不變 | Manus 無法即時取得 Claude 草稿 |
| C. 本草稿：Manus 呼叫 Messages API | 如第 2 節 | 自動化最高 | 金鑰、費用、同源偏誤 |
| D. 反向：Claude 總召呼叫 Manus | Claude 觸發 Manus 任務 | 金鑰在 Claude 側 | 需 Manus 提供 API（UNKNOWN） |

建議順序：先以 B 運行並累積「搬運次數／重寫比例」資料，資料顯示痛點成立再試 C 的最小版本（單一用途、單一模型）。這是推薦，不是已決定；是否做 C 由 MIKO 決定。

## 7. 驗收條件（若採用 C 的試行）

| AC | 條件 | 證據 |
|---|---|---|
| AC1 | 金鑰只存在於平台密鑰設定；repo、PR、日誌全文搜尋無金鑰樣式 | 搜尋命令與輸出 |
| AC2 | 已設用量／支出上限，值由 MIKO 確認 | 主控台設定畫面（由 MIKO 提供） |
| AC3 | 10 次試呼叫輸出均落在 proposals/，首行「未驗收提案」，尾註齊全 | 檔案清單與 SHA-256 |
| AC4 | 0 個呼叫輸出直接出現在 skills/、.github/、tests/、VERSION、sync/ | git diff 路徑檢查 |
| AC5 | 全部經 PR 並由 Claude 治理總召審查 | PR 紀錄 |
| AC6 | 硬禁止回歸：以固定輸入要求下單腳本，Claude 回覆拒絕且標硬禁止 | 輸入與回覆原文 |
| AC7 | check_repo C1～C16 全過 | 命令輸出 |
| AC8 | 試行結束後有成本與重寫比例統計，供停用／續用判斷 | 統計表 |

停用條件：任一金鑰疑似外洩、支出超過上限、AC4 出現違規、MIKO 說停止。

## 8. ADR 草稿

> 編號：UNKNOWN（撰寫時 VERSION 第 3 行為 ADR-095；下一號由 Claude 治理總召於併入時指派，不在此預占）。格式：草稿，採用前須依治理總召慣例整理成 README／CHANGELOG 單行格式。

```
ADR-UNKNOWN：Manus 透過 Messages API 呼叫 Claude（草稿）
狀態：PROPOSED（未驗收提案；MIKO 未批准）
背景：Manus 為 knowledge-cards/ 總召（ADR-088），草稿常需 Claude 協助；目前靠 MIKO 人工搬運。
決定（若採用）：
  1. 允許 Manus 以專用金鑰呼叫 Messages API，限提案草稿用途。
  2. 模型分級：輕量 claude-haiku-5-5；重量 claude-sonnet-5-5；最困難 claude-fable-5-2；Manus 不呼叫 Opus 做改正本或放行。
  3. 金鑰只放 Manus 平台密鑰設定，設支出上限，不進版控。
  4. 輸出只落 knowledge-cards/proposals/，首行「未驗收提案」，尾註模型、日期、SHA-256。
  5. 審查、放行、版本號仍由 Claude 治理總召；併入受保護路徑須 MIKO 逐件、當次明確批准。
  6. 不得用此通道做下單、交易、Broker、LIVE 或繞道；台指期維持停止。
替代方案：A 現狀；B 只讀正本不給 API（建議先行）；D 反向呼叫。
後果：新增金鑰與費用風險；降低搬運成本；同源偏誤須靠獨立稽核管理。
撤銷條件：MIKO 說停止；金鑰外洩；支出超限；出現繞過審查事件。
驗證：見本文件第 7 節 AC1～AC8。
```
