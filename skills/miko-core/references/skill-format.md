領域 Skill 必含四節：問問題（必問項與預設值）、解決（可執行步驟：用哪個工具、輸入、輸出，含資料取不到時的備援路徑）、後設（該領域常見錯誤）、檢查（驗收條件＋一題實跑題與通過條件）。開頭寫明：負責什麼（一個 Skill 只做一件事）、看哪些資料、接哪些連接器、有沒有排程、交回什麼、哪些事先問 MIKO。缺可執行步驟，或實跑題沒跑通的領域 Skill，不得標為已採用。「解決」步驟有先後依賴時（後一步要用前一步的輸出），依序編號，每步寫輸入、輸出與閘門（什麼結果就停止或降級、不往下做）；前一步沒完成不得跳到後面，取不到依 §2.7 標 NOT_READ（領域標籤從其規定）並只停相依步驟。這條「逐步寫輸入、輸出與閘門」的規定自正本 1.2.25 起適用於：新寫的領域 Skill，以及改動「解決」節步驟的既有 Skill 改版（只改錯字、版號或其他節不算）；適用而沒寫齊的，不得標為已採用。1.2.25 之前已採用的 Skill 不因這條改判未採用，下次改動「解決」節步驟時補齊；1.2.25 之前寫好但還沒採用的 Skill，送採用時視同新寫；§0 ⑤ 體檢時列出尚未補齊的 Skill。順序範例：dghp-beauty §2 六步（第 1、3、4、5 步正文未逐步寫閘門，屬待補齊）（ADR-048；適用範圍 ADR-049 釐清）。dghp-beauty v0.6（正本 1.2.27，ADR-050）已補齊六步的輸入、輸出與閘門，前一句的「待補齊」保留為歷史；1.2.26 的註記漏列第 6 步（閘門寫在步外的「排名規則」列），也沒註第 2、3、5 步的輸入缺口，依下方判定標準更正（1.2.26 補稽核 P5）。本條用詞定義（ADR-050，1.2.26 補稽核 P1～P3）：「已採用」＝已推上本 repo main 的 Skill，登記在 skills/README.md「領域 Skill 採用狀態」表；還沒進 main 的是未採用草稿。「解決」節＝§2.4 四節中寫可執行步驟的那一節，不論節名（例如 tw-alert-check「流程」、gmail-cleanup「清理判定」、tw-backtest-workflow 的兩個「解決」節）。「寫齊」的判定標準：每一步本行或其下縮排子項寫出輸入、輸出與閘門，寫在步外的列不算。補齊範圍：改動「解決」節任一步驟時，整節所有有先後依賴的步驟一起補齊，不只補改到的那一步。
指令六欄（ADR-058；MIKO 2026-11-08 指示寫進未來 Skill 的格式）：Skill 裡每一個指令條目（「解決」節的每一步，以及四節中以「必須」「一律」「不得」「禁止」等寫成必做或禁止的條目）都寫六欄：(1) ID：Skill 內唯一（例如 S1、S2），改版不重用已刪除的 ID；(2) 觸發條件：什麼情況必須執行；(3) 操作要求：具體做什麼（用哪個工具、輸入、輸出）；(4) 禁止事項：什麼情況不得執行或不得怎麼做，沒有就寫「無」；(5) 驗收證據：用什麼證明完成（工具輸出、檔名、讀回 SHA-256、測題結果）；(6) 失敗處理：失敗時標哪個明確狀態（NOT_READ、UNKNOWN、BLOCKED、NOT_RUN、領域標籤如 NOT_RETRIEVED，或正本已定義的其他明確狀態如 CONFLICT），以及只停哪些相依步驟。六欄可寫成表格，或每條本行與其下縮排子項；上一段的「輸入、輸出與閘門」照舊適用，輸入與輸出寫在操作要求欄、閘門寫在失敗處理欄即算寫齊。適用範圍：自正本 1.2.35 起新寫的 Skill，以及新增或改動指令條目的既有 Skill 改版（只改錯字、版號不算），改到的條目所在的整節一起補齊；適用而缺欄的不得標為已採用。1.2.35 之前已採用的 Skill 不因本條改判未採用，下次改動時補齊；miko-core 與 multi-agent-coordination-engine 是核心規則、不是可執行步驟清單，不套用本條，除非 MIKO 指定。MIKO 2026-11-08 交總召決定（原話「你決定」）：miko-core 只在 §1 開工對齊、§1.1 收工、§2.7 困難卡、§5 品質閘門四段套用，以 §5.1「核心指令六欄表」呈現；其他段與 multi-agent-coordination-engine 仍不套用（ADR-060）。1.2.41 另加 §3 通用「做成 skill」一列 K15（ADR-064）。補齊狀態記在 skills/README.md 採用狀態表下方的註記。六欄之外的類型欄（P／C／J）見下段「執行類型」與 make-skill §2 七欄表。
執行類型（ADR-064；MIKO 2026-11-08「skill 內容要全部升級變成可執行性操作」）：指令六欄之外，每個指令條目再標一個類型：P＝程式步（整步由程式完成，結果能算出或查表得到；操作要求寫命令、輸入檔、輸出檔，驗收證據是結束碼與輸出檔，模型不得手算或手填代替）；C＝檢查步（模型做，做完必須跑指定的檢查腳本、命令或固定清單，不過不往下）；J＝判斷步（只能靠模型判斷，附固定測題 expected／forbidden 與相近反例）。結果能用程式算出或查表得到的步驟不得標 C 或 J；一步裡混有模型判斷的不得標 P。寫法用 make-skill 的七欄表（ID、類型、觸發條件、操作要求、禁止事項、驗收證據、失敗處理），格式可用 skills/make-skill/scripts/skill_lint.py 檢查（lint PASS 只代表格式，不代表可執行）。適用範圍和指令六欄相同：自正本 1.2.41 起新寫的 Skill，以及新增或改動指令條目的既有 Skill 改版；之前已採用的下次改動時補齊。miko-core 只在 §5.1 加類型欄與 K15（做成 skill），其他段不套用；K15 是 ADR-060 四段之外本版新增的一列（ADR-064，總召依 MIKO 2026-11-08「你決定」授權）。
