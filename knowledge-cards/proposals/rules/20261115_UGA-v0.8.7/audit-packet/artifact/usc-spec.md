# Skill 契約（Skill Contract, SKL，原 USC）：九契約、四節、P／C／J 七欄

## 1. 目的與範圍

規定所有 MIKO Skill 必須具備的九項必要契約、四節文件格式（問問題、解決、後設、檢查，與正本 miko-core 附檔 skill-format.md 同名同序），以及 P/C/J 七欄步驟表。製作流程由 UCP 管轄；本契約不定義十六章。

## 2. 九項必要契約

| 契約 | ID | 必須包含 | 檢查方式 |
|---|---|---|---|
| 識別 | USC-C1 | `name`、`name_en`、`version`、`owner_role`、`status` | front matter 欄位齊全 |
| 觸發 | USC-C2 | 何時觸發、何時不觸發、相近反例 | 三類各至少一例 |
| 輸入 | USC-C3 | 必備輸入、選用輸入、來源要求、缺資料處理 | 每個輸入有型別與來源 |
| 輸出 | USC-C4 | 輸出格式、輸出狀態、禁止輸出 | 輸出可被第三方檢核 |
| 步驟 | USC-C5 | P/C/J 七欄步驟表 | 每列七欄齊全、ID 唯一 |
| 邊界與禁止 | USC-C6 | 硬禁止、授權需求、資料分級 | 硬禁止以絕對語句列出 |
| 失敗與回復 | USC-C7 | 失敗出口、重試上限、回復路徑 | 重試上限為有限整數 |
| 驗收與測試 | USC-C8 | AC、測題、expected／forbidden、狀態 | 每條 AC 有測題 |
| 版本與維護 | USC-C9 | 版本、日期、變更紀錄、快照、退役規則 | SemVer 與日期齊全 |

## 3. 四節格式

| 節 | 標題 | 承接契約 | 必備內容 |
|---|---|---|---|
| 一 | 問問題 | C1、C2、C6 | 開頭六項（負責什麼、看哪些資料、接哪些連接器、有沒有排程、交回什麼、哪些先問 MIKO）、必問項與預設值、觸發／不觸發／反例、硬禁止與授權需求 |
| 二 | 解決 | C3、C4、C5 | 輸入與來源、輸出與狀態、P/C/J 七欄步驟表，每一步寫輸入、輸出與閘門 |
| 三 | 後設 | C8 | 該領域常見錯誤、最強反例、偽陽性與偽陰性清單 |
| 四 | 檢查 | C7、C8、C9 | AC 與測題、expected／forbidden、失敗出口與有界重試、版本與退役、證據位置 |

四節名稱與順序以正本為準，候選 v0.4.0 以前使用的 S1 目的範圍觸發、S2 工作流程、S3 檢查驗收測試、S4 失敗回復版本交接自 v0.5.0 起停用。停用不代表內容丟失，原 S1 的識別與觸發併入問問題，原 S2 的步驟表併入解決，原 S3 的 AC 與測題併入檢查，原 S4 的失敗出口與重試併入檢查，版本與交接移到問問題的開頭六項與檢查的版本段。四節任一節缺必備內容，或順序與名稱與正本不同，即判不合格。

## 4. P/C/J 七欄步驟表

| 欄位 | 說明 |
|---|---|
| ID | `<SKILL>-S<n>`，唯一且不重用 |
| 類型 | `P` 程式步／`C` 檢查步／`J` 判斷步 |
| 觸發條件 | 何時執行此步 |
| 操作要求 | 必須做什麼 |
| 禁止事項 | 不得做什麼 |
| 驗收證據 | 產出什麼可檢證據 |
| 失敗處理 | 失敗時的狀態與出口 |

規則：「失敗處理」欄必須涵蓋 USC-C3 定義的缺資料情境（缺資料 → `NOT_READ`／`BLOCKED`）；`C` 步完成後必須跑指定檢查；`J` 步必須寫 expected／forbidden 或固定反例；同一 Skill 內 ID 不得重複；七欄缺一即不合格。

## 5. 與 UAC／UCP 的邊界

USC 不定義十六章、不定義閉環順序、不定義路由演算法。Skill 若需要十六章結構，一律引用 UAC。Skill 的製作與驗收仍走 UCP A00～A13。引用時只取章節骨架與欄位名稱，不得把文件架構（元件、介面、資料流）寫入 Skill 本體；Skill 若需要描述自身結構，寫在後設節，不複製 UAC 第五章。

## 6. 名稱對照
本文件原稱 Universal Skill Contract（USC），自 0.8.7 起改稱 Skill 契約（SKL），識別碼與檔名維持 usc-spec；條文編號不變。
