- 提示詞與 Skill 行為驗證（ADR-041；由 dghp-prompt-evaluation 去重後併入，展開上方 ADR-036 的 A/B 對照；只在修改提示詞或 Skill、比較新舊規則、驗證行為是否改善時使用，普通回答不自動跑基準測試）：
  - 目的：確認規則真的改善指定任務，同時保持原有的保真、權限與未知語意。
  - 案例：既有的固定案例可讀且適用就當基礎案例，再補實際遇到的可重現錯誤；既有案例在指定位置找不到標 NOT_FOUND_IN_SCOPED_LOCATION，不可讀標 BLOCKED／UNAVAILABLE，兩者不混用。本輪案例另存到已授權的隔離位置，不宣稱已跑原案例包。
  - 固定對照條件：任務、模型與版本、有效指令、工具、資料、權限、預算與驗收規則；以本輪實際讀到的版本或 SHA-256 區分基準版與候選版；控制不了的列為限制。
  - 先定 expected（應出現）與 forbidden（不得出現）再跑，不看答案後放寬評分；expected 的數值、日期與判定，能算的用程式核算，不能算的交給獨立覆核（ADR-064）。案例含正常、邊界、對抗／提示注入、缺資料、衝突、唯讀、副作用。
  - 在隔離、沒有正式資料存取的環境跑；外部發布、交易、危險刪除只模擬，或檢查是否拒絕越權；付費 API 只在已授權預算內使用。
  - 保存實際輸入、輸出、工具軌跡、適用的指令來源、判定理由與證據位置；密鑰與私密內容先遮罩。測例含金鑰、密碼或個資時，一律用 `<KEY>`（或 `<PASSWORD>`、`<PII>`）佔位，不得自造仿真字串（ADR-046）。
  - 逐案標 PASS／FAIL／NOT_RUN／BLOCKED，不填虛構分數；沒有完整分母不給百分比；一次測試只證明該次案例，不保證模型每次遵守，不宣稱「最強」「100%」。
  - 顯式調用與自然觸發分開測；沒量測的延遲、token、成本標 UNKNOWN；狀態分層、自測與獨立重跑分開，依下方「證據與狀態（ADR-040）」。
  - 基準版怎麼選（ADR-061；2026-11-08 對照 Anthropic 官方 skill-creator 的測試方法）：改版既有 Skill 時，基準版是舊版；新寫的 Skill 沒有舊版，基準版是同一題、同條件但不載入該 Skill，兩邊都跑，才能證明新 Skill 比沒裝時好；不載入的基準版記為「無該 Skill」，並記下當時仍載入的核心 Skill 與帳號偏好版本（同條件指這些照常載入）；只跑有載入的一邊時，結論只寫該次案例 PASS／FAIL，不寫「比沒裝好」。
  - 自然觸發要加相近反例：除了應觸發的題，至少加一題用字或領域相近、但不該觸發這個 Skill 的題（例如句子提到天氣、其實在問吃什麼），檢查有沒有誤觸發或搶走別的 Skill；反例題同樣先定 expected／forbidden。
  - 新規則造成迴歸時：保留對照、最小修補、重跑受影響案例，不刪失敗紀錄。升格由 MIKO 決定；沒跑的案例標 NOT_RUN，不用檔案自檢代替。
  - 修規則要對準通則（ADR-061；同上來源「別只修例子」，MIKO 2026-11-08 指示加入）：測題 FAIL 後修規則，要改掉造成失敗的通則，不是只讓那一題過；修完除了重跑失敗題，再加至少一題沒拿來修規則的新題（同類情境、不同說法）一起驗；新題沒跑前標 NOT_RUN，不說「已修好」。
    - 新題的用詞（1.2.45，SGN 重跑報告 P15，總召同意）：新題的題目、觸發詞與 forbidden 不得照抄這次修補新增的關鍵用詞或例詞（例如修補句新增例詞「已上線」，新題的 forbidden 就不再用「已上線」）；領域名稱、狀態標籤等固定名詞（例如台指期、STOPPED_BY_USER）不算；照抄的不算「不同說法」的新題，要另寫一題。
  - 評估面：需求完成度、保真、錯誤、工具使用、越權、不必要的停頓。
  - 交付：模型與工具環境、對照版本、逐案結果、證據位置、改善與退步、尚未驗證項。
  - 需要開新對話或子代理才能做到隔離或自然觸發測試時，依 independent-audit 的冷啟動方式進行，算下方「多代理」條的獨立稽核用途。
