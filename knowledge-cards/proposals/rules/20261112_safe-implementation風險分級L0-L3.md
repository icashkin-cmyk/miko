## 一、要加進 safe-implementation 的文字（插在「解決」第 1 步之前，成為第 0 步；其餘步驟編號不動）

0. 判風險等級（先於任何修改；回報第一行寫等級與一句理由）：
   - 第 0 層，不適用分級，先判這層：下單、交易、Broker、LIVE 是硬禁止（MIKO 當次明說也不做，只能由 MIKO 自己操作）；台指期是 STOPPED_BY_USER（只回該標籤，不做）；回測是 PAUSED_BY_USER（固定樣本的引擎回歸檢查 C6、C9 為例外，ADR-074）；金鑰不索取、不寫進任何檔案。碰到這一層，後面的 L0～L3 與確認都不能解除它。
   - L0（文件錯字、註解、格式、不改行為的重命名）：直接做；檢查 diff 與基本靜態檢查。
   - L1（單一功能、測試、局部修補、讀取來源的資料處理）：照下方第 1～8 步；方案寫一兩句即可；跑相稱的測試。
   - L2（設定、共用介面、資料或儲存結構、CI 或 workflow、Skill 或正本、會寫入雲端或 GitHub 的動作）：先列影響範圍、相容性與回復方式（miko-core §2.3 BLOCKED 句）；Skill 與正本走獨立稽核；寫入一律分支加 PR，不直推 main。
   - L3（不可逆或對外：推送 main、合併、刪除、發送、部署、費用、權限變更）：停在可逆的準備完成狀態；寫出精確內容（diff 或檔名）、回復方式，等 MIKO 當次明確批准（引用該則訊息）；常設授權不算（README 跨平台寫入須當次明確授權）。
   - 判定規則：同一任務含不同等級，取最高；觸及認證、付款、個資、刪除、公開發布至少 L2；不可逆、對外發送、改真實資料、影響其他人視為 L3；拿不準時往高一級。
