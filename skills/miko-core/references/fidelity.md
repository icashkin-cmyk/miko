- 整理、重構、去重的保真細則（ADR-041；由 dghp-fidelity-restructure 去重後併入，補充上方「Skill 與規則改版」與帳號偏好的資料保真；單純提到 Skill、要求摘要或解釋、執行既有 Skill 時不套用）：
  - 輸入要有實際可讀的原始來源、版本或日期、要的輸出格式與使用者授權範圍。
  - 只有使用者明確授權摘要時才刪減資訊；否則交付完整可用成果，需要檔案時依指定格式產出。
  - 全篇重構先讀完整範圍，盤點章節、條款、表格欄位、公式、條件、例外、依賴、來源與附件；來源缺頁、截斷、缺附件或同名異文標 UNKNOWN／CONFLICT，不用檔名、記憶或舊摘要補原文。
  - 建「來源位置 → 輸出位置」對照；保留數值、單位、日期、版本、名稱、順序、否定、邊界、未知、衝突與來源；格式屬於規格時格式也保留。
  - 分 DATA（資料）／STRUCTURE（結構）／FORMAT（格式）／SEMANTIC（語意）四層保真，只改使用者授權的層；未授權不重新設計流程或改名稱。
  - 去重前比完整作用域、前提、限制與例外；只有完全等價且沒有獨有資訊才移除，相似不等於重複；衝突列出兩版，不私自以最新日期當正式權威。
  - 編譯成程序時，逐條對應輸入、前提、動作、輸出、PASS／FAIL／UNKNOWN 與例外。原文沒定義的規則、門檻、資料或授權列「待決定」，不自行創造；與 §2.1「合理假設並標註」的界線：低風險、可逆的格式或表達細節可假設並標註，規則、門檻、資料、授權不假設。
  - 新能力先寫成候選、延伸或補丁，不宣稱已上線（凍結與換版依下方「證據與狀態（ADR-040）」；經獨立稽核與 MIKO 選定後，才依 §6 治理房收件併入正本）；使用者要求「原文在上、編譯在下」等布局時照做。
  - 交付前做遺漏查核：章節覆蓋、數字／公式／日期、否定與例外、來源對照、狀態詞、欄位與順序；總字數相近不是保真的證明。交付含來源對照與真正需要決定的差異；可貼用的規格放單一 Code Block。
  - 自訂指令欄超過字數上限時，保留完整檔並分層掛載，不靜默截斷。
  - 多版迭代與字數壓縮的逐版比對（ADR-056；2026-11-07 精簡 GPT 自訂指令時，第三版只驗字數與讀回，複查才發現漏 4 處：換底本時搬走的段落消失、兩條硬邊界被壓掉、否定句被判「已涵蓋」刪掉；MIKO 指示「全部都是這樣處理」）：精簡、改寫、合併或壓字數的規則與指令文字（Skill、帳號偏好、平台自訂指令、Prompt、SOP；為符合字數上限而壓縮也適用，不屬於本細則開頭「要求摘要」的排除），每一版交付前都做三項比對並在回覆附結果（有程式環境用程式；沒有程式環境時手動逐子句列表並標「手動比對」，不得省略）：(1) 對每一份原文逐子句比對，沒逐字保留的逐條列出處置（改寫、搬到哪裡或刪除）與理由；(2) 壓縮前先從原文列出硬邊界與必含條件清單，交付時逐項確認存在；(3) 用程式比對跨欄或跨檔的重複，並逐項檢查過時用語。否定、例外、數值、條件不得以「已涵蓋」刪除，除非指出涵蓋它的那一句。底本中途更換（例如使用者後來貼出原文）時，重做比對與變更表。只驗字數、SHA-256 或讀回不算保真驗收；沒跑比對標 NOT_RUN，不說「無誤」。
