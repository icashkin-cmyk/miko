# dghp-metaphysical-integrated-analysis v0.1｜命理與關係象徵分析｜2026-10-30

來源：他房候選 1.0.0-CANDIDATE（2026-10-30 轉入），治理房改寫成 MIKO 領域 Skill 格式（ADR-025）。
負責：命盤、合盤、流年流月、起卦與多系統交叉的象徵性解讀。不做科學、醫療、法律、投資、人身安全判定；不做人物搜尋或背景調查。
看哪些資料：使用者提供的出生資料、命盤截圖、現實互動描述；計算用 lunar-python（八字、節氣、大運）與 ephem（行星黃經）。
連接器：程式執行；使用者上傳的圖表。無排程。
狀態來源：專案檔「命理_個人資料.md」（每人一節：出生資料、來源、已驗證計算、衝突紀錄、更新日）。個人與第三人的資料不寫進本 Skill 或公開 repo。開工時讀；讀不到標 NOT_READ。
交回：各系統可算的結果與候選盤、象徵解讀、重要 UNKNOWN 與 CONFLICT、整合結論。
先問使用者：要分析的對象、年份或月份；更新個人資料檔（衝突時先列新舊值，確認後才改）。

## 1. 問問題
- 單人：西元出生年月日、出生地（城市、國家）、出生時間（精確分鐘最好；只有時辰或區間就保留區間）、傳統排法需要時才問性別（只用於計算）。
- 合盤：每人分開建檔，不把 A 的資料補進 B；關係背景（朋友、伴侶、曖昧、未知）；使用者觀察到的現實互動（標【使用者】）。
- 起卦：數字或起局時間、採用的算法；沒指定就先寫明採用哪一種。
- 資料夠做一部分就先做可靠的部分，不把「補資料」當固定追問；只要求真正能提高品質的最小資料。

## 2. 解決（先算後解讀；不能算的標 NOT_CALCULABLE，不用記憶補值）
1. 八字：`pip install lunar-python ephem`（系統 setuptools 太舊時改用 venv）。`Solar.fromYmdHms(...).getLunar().getEightChar()` 取四柱；晚子時（23:00–23:59）一律並列：
   - 候選 A：夜子時派，日柱不換、時柱用次日（`setSect(2)`）。
   - 候選 B：23:00 換日（`setSect(1)`）。
   - 使用者或他房提供的其他排法（例如時柱沿用當日日干）列為候選 A′，標 CONFLICT，不自行挑一盤。
   - 真太陽時：經度修正加均時差；若讓時間跨過 00:00 或時辰邊界，再列一個候選並寫出影響哪些判讀。
   - 大運寫明順逆、起運法與流派差異；神煞只作低權重輔助。
2. 西洋占星：ephem 算行星黃經（熱帶黃道、地心、當時曆元），ASC 與 MC 用恆星時公式；出生時間是區間就輸出區間，跨星座或宮位就保留候選；同星座不等於合相，相位看實際角距與容許度。ephem 沒有的點（例如交點）標 NOT_CALCULABLE 或用使用者提供的星盤。
3. 紫微斗數、人類圖：沒有可靠排盤引擎，只讀使用者提供的命盤或圖表，標 USER_PROVIDED_CHART，不假稱重新計算；資料不足時命宮、四化落宮等精確層整層標資料不足。
4. 易經梅花：先固定算法。三數法：第一數除 8 取上卦、第二數除 8 取下卦、第三數除 6 取動爻，餘 0 視為 8 或 6；1 乾 2 兌 3 離 4 震 5 巽 6 坎 7 艮 8 坤。列算式、本卦、互卦、變卦、動爻、體用與五行生剋；其他流派要標差異。
5. 奇門遁甲需起局日期、時間、地點、時區與排法，缺一不捏造局數、值符、值使；九宮飛星沒有坐向與平面資料只做年度一般方位。顏色、水晶、符令等只標民俗或信仰實踐，不保證化煞、招財、治病或挽回。
6. 關係分析分層寫：友情基礎、溝通相容、浪漫吸引的象徵、行動與衝突張力、親密或身體張力的象徵、情緒穩定、主導與界線、理想化或誤讀風險、修復能力、長期條件、現實驗證。現實行為（主動、時間投入、承諾履行、衝突後修復、責任對等）的權重高於象徵相位。同性關係不套用男方女方角色。多人比較每一對分開建立，不把 A×B 推論成 B×C；資料完整度不同時，不能寫成「一定比較適合」，只能寫「可觀察的象徵結構較完整」。
7. 流年流月：分析年份要明示；八字流年按節氣換年，流月按節氣月並明示，不與農曆月混稱；行運以實際天象驗算，不編造逆行或食相。「血光之災」一律改寫成健康、交通、跌倒、疲勞、衝突等注意窗口，不說必然發生。
8. 多系統交叉：三個以上同方向只能寫「共同象徵訊號較強」，兩個同方向是「中度象徵支持」，分歧保留 CONFLICT，不能算的不計票；人類圖只用於人格與決策風格，不當事件預測的同權票；分數若有，只能叫象徵一致度，不是機率。
- 標籤：計算結果標【工具】，使用者資料標【使用者】，傳統象徵解讀標【傳統解讀】（流程鎖計入降級），多訊號整合標【推論】，不能判定標【UNKNOWN】。UNKNOWN 不等於否定；沒有盤不等於沒有該特質。
- 輸出順序：最重要結論、已知資料與最大限制、各系統主要訊號、逐題回答、關係與現實校準、重要 UNKNOWN 與 CONFLICT、整合。使用者說「完整」才展開全部計算。

## 3. 後設（常見錯誤）
- 先下結論再補盤；用模型記憶填干支、度數或落宮。
- 晚子時只選一盤；不同軟體或流派的時柱差異沒列出來。
- 把多系統同方向寫成「證明」；把象徵寫成事件機率。
- 從命盤推定第三人愛不愛、想不想發生關係、性傾向、忠誠、疾病或心理狀態；只能寫「象徵」，實際意願標 UNKNOWN，除非本人明確表達且使用者提供。
- 把使用者描述的互動直接升級成已驗證事實。
- 把個人或第三人的出生資料寫進 Skill 或公開檔案。

## 4. 檢查
- AC-M1：每個計算結果寫明工具或算法；不能算的標 NOT_CALCULABLE。
- AC-M2：晚子時與流派差異至少並列兩個候選，衝突標 CONFLICT。
- AC-M3：象徵解讀與現實事實分開標示；沒有任何第三人真實意願、性慾、性傾向的斷言。
- AC-M4：多系統交叉照計票規則，不出現「證明」。
- AC-M5：個人資料只來自「命理_個人資料.md」或本輪使用者輸入，新舊衝突時先列出、不靜默覆寫。
- AC-M6：輸出順序符合本節規定，沒有把治理術語當答案。
- 實跑題：「某人晚子時出生，排八字並列候選。」通過條件：至少列 A、B 兩盤並寫出換日規則；若有第三種排法標 CONFLICT；有真太陽時是否跨日的說明。
- 實跑紀錄（2026-10-30）：用 lunar-python 與 ephem 重算一個晚子時樣本。候選 B 與來源一致；來源的候選 A 時柱和 lunar-python 夜子時派不同（來源沿用當日日干，lunar-python 用次日日干），改列 A 與 A′ 並標 CONFLICT；行星黃經與來源區間差距在 1 角分內；真太陽時約比民用時快 11 分鐘，區間最後約 10 分鐘會跨過真太陽時午夜。
