# photo-inspection-log v0.18｜施工查驗照片整理（依公司範本）｜2026-11-04

v0.18：流程採 v0.17（整包＋範本＋build_company＋preflight）；v0.17 精簡時拿掉的 v0.16 抄寫、詞庫、物件辨識、回覆格式、常見錯誤、偏旁表、驗收條目全部補回（舊版 export 步驟已由 build_company 取代，其餘照舊適用）。

- 負責：把查驗白板照片抄寫、確認，輸出公司格式「材料自主檢查照片.xlsx」；只交這一個檔，有待確認時另交放大圖；工作資料存在交付檔的隱藏工作表，下次上傳它就能接續。
- 資料：聊天上傳的照片或 zip、Google Drive 照片資料夾（只讀）、已連線電腦的照片資料夾、上次的材料自主檢查照片.xlsx。

## 一、整包取得（缺一不可）
本 Skill 必須整包使用，檔案一起下載，缺少範本就停止，不得自行排版。
- 必要檔案（GitHub icashkin-cmyk/miko 的 skills/photo-inspection-log/）：
  - scripts/材料自主檢查照片_範本.xlsx（範本分頁＋10 個材料表分頁，版面與名詞的唯一依據）
  - scripts/build_company.py（依範本版面產出 Excel）
  - scripts/make_entries.py（照片紀錄 → entries.json）
  - scripts/log_photo.py（白板照片讀取、抄寫、詞庫、回覆格式）
  - scripts/forms.csv（材料表名詞，給 log_photo.py terms 與詞庫用）
  - scripts/preflight.py（開工與交檔的防呆檢查）
- 下載（每個新對話執行一次，逐一下載，任一失敗就停止並告知使用者）：
  `mkdir -p work/scripts && cd work && B=https://raw.githubusercontent.com/icashkin-cmyk/miko/main/skills/photo-inspection-log/scripts && for f in log_photo.py build_company.py make_entries.py forms.csv preflight.py; do curl -sSLf -o scripts/$f $B/$f; done && curl -sSLf -o scripts/材料自主檢查照片_範本.xlsx "$B/材料自主檢查照片_範本.xlsx"`
- 下載失敗（網路被擋）：請使用者直接上傳整包 zip；不得只用其中一部分，也不得自行改寫程式。

## 一之二、防呆（一條龍，必須遵守）
- 開工第一步：`python3 scripts/preflight.py start`。任一項 FAIL 就停止，請使用者上傳整包 zip，不得開始處理照片。
- 交檔前：`python3 scripts/preflight.py deliver 材料自主檢查照片.xlsx entries.json`。任一項 FAIL 不得交檔。
- 不得使用 `log_photo.py export`（已停用，會回傳結束碼 7）。交付檔只能由 build_company.py 產生。
- 範本與材料表是唯一版面與名詞依據；範本中不得有公式（已清除，preflight 會檢查）。

## 二、流程
0. 開工：`python3 scripts/preflight.py start`（必須全部 PASS）。
1. 接續：使用者上傳上次的材料自主檢查照片.xlsx → `python3 scripts/log_photo.py restore 材料自主檢查照片.xlsx 照片紀錄.xlsx`。沒上傳 → 新建工作檔。
2. 收照片：放進 incoming/（zip 直接給 zip 路徑）。超過 20 張請使用者改傳 zip、Drive 資料夾或已連線電腦的資料夾。`python3 scripts/log_photo.py prep incoming 照片紀錄.xlsx`：SHA-256 去重、讀 EXIF、依拍攝時間排序、轉正、產生判讀圖與格線圖、抄寫範本 text/NNN.tpl。
   - 抄白板：看 photos/NNN_grid.jpg，複製範本成 text/NNN.txt（格式見「工作檔」）。抄之前先看 `glossary`（詞庫、已確認詞彙）與 `terms`（材料表名詞）；字形相同就照寫，不再問。固定欄位（工程名稱、監造單位、承造單位）寫 fixed/NNN.txt。
   - 讀不清：`crops` 放大（左原圖、右增強）、查簡體偏旁、對照工地常用詞與材料表；型號仍不確定就網路搜尋「品牌＋型號」，官方型錄或經銷頁完全相同才寫入並 `vocab` 記來源網址；都不行就寫〔?〕。
   - 檢查：逐行數字數防漏字；OpenCC（s2t）只當偵測器逐字判斷。
   - 寫入：`python3 scripts/log_photo.py addmany 照片紀錄.xlsx`（百張時每 10 張一次、回一行進度；中斷後依 manifest.csv 的 todo 繼續）；寫入後 `check`、`glossary` 看「疑似同物不同寫法」。
3. 產生 entries：`python3 scripts/make_entries.py 照片紀錄.xlsx entries.json photos_out`。
4. 填欄位（Claude 負責，依下列規則，寫入 entries.json）：
   - sec（分項工程名稱）：白板沒有；使用者給了就填，沒給就留空並在回覆問（一個查驗項目一題）。
   - item（檢查項目）：查驗項目去掉「材料進場」；能對到材料表就用材料表的「材料/設備名稱」。
   - design（設計/標準值）：對到材料表（範本內的材料表分頁）就用材料表的品質管理標準，第一行寫材料名稱；對不到就用白板規格，並在回覆列為「未建檔」。
   - measured（實測值）：白板有實測就照寫；白板沒有實測欄的，留空並在回覆說明（【待填】）。
   - shot / loc / bldg：照 make_entries.py 產生的值；棟別留空，由使用者提供。
5. 產出：`python3 scripts/build_company.py entries.json 材料自主檢查照片.xlsx 照片紀錄.xlsx`（版面複製自範本，每頁 3 筆，A4 直式）。第三個參數一定要給：工作資料（原文、基準、分項工程、已確認詞彙）會存進交付檔的隱藏工作表，下次第 1 步 restore 才能接續；沒給 restore 會 STOP。
6. 檢查：用 LibreOffice 轉 PDF 抽看，照片在格內、文字沒有截斷；確認筆數＝entries 筆數、頁數＝ceil(筆數/3)。
7. 交檔：只交「材料自主檢查照片.xlsx」（SendUserFile），交檔前 preflight deliver 全部 PASS；有〔?N〕就附 `crops photos/NNN.jpg 待確認_MM-DD_第N張.png 編號:x0,y0,x1,y1 ...`（編號＝〔?N〕號）。
8. 使用者回覆：`fix 照片紀錄.xlsx 分頁:列號 "原文字（含〔?N〕）" "確認後"`（同時記進已確認詞彙；改到日期會自動搬到該日分頁）；分項工程名稱用 `sub 照片紀錄.xlsx "查驗項目" "分項工程名稱"`；自己抄錯用 `set`（不記進已確認詞彙）→ 重跑第 3～7 步交檔。
- 觸發（使用者指定）：使用者在聊天室丟照片＝要整理、更新，不先問要不要做、不先給計畫，直接跑完整流程交檔；只在讀不清的字、固定欄位不符時集中問。
- Excel：使用者指定此流程用 Excel，屬本流程的例外，不擴及其他任務。

## 二之二、公司規則（填 entries.json 時套用；版面一律以範本為準，下列版面描述僅供核對）
- A4 直式、標楷體；每頁標題「材料自主檢查照片」（3 列合併、14 點）＋3 張照片＋頁碼；（v0.17 起交付檔依範本為單一分頁；工作檔仍每天一個分頁。）
- 每張 14 列：左 A:E 照片（固定在格子、置中）；右 F:I：分項工程名稱／檢查項目（3 列）、設計/標準值｜實測值（欄頭 1 列＋內容 7 列）、拍攝時間（民國，例 115年10月8日）、拍攝位置：工區內、棟別/層別/空間編號/空間位置（白板有位置就接在冒號後）。
- 公司規則：
  - 檢查項目：查驗項目去掉「材料進場」；對得到公司材料自主檢查表就用表上的材料/設備名稱（例 線槽 → 鋁製電纜線架）。
  - 設計/標準值：對得到自主檢查表就用表上的品質管理標準，第一行寫材料名稱（例 鋁製電纜線架／廠牌:XX／直式電纜線架 300Wx100Hx3000L…）；同名多張用白板型號、規格數字比對，比不出唯一一張就用白板規格。對不到就用白板規格欄。
  - 實測值：白板實測都對得上白板規格＝相符，實測值與設計/標準值同寫；不相符或對不到自主檢查表，就照白板實測（含數量）；白板沒有實測欄就照白板內容。
  - 白板品名換成公司寫法（例 鋁梯型直式 → 直式電纜線架，以材料表寫法為準）；新增對照先問使用者。
  - 分項工程名稱：白板沒有；使用者給了就 `sub` 記住，之後同一查驗項目自動帶入；未填顯示【待確認】並在回覆問一次（一個查驗項目一題）。
  - 拍攝時間用照片日期換民國；沒有照片日期用查驗時間；都沒有留空並在回覆說明。

## 工作檔（照片紀錄.xlsx，只在工作目錄，不交付）
- 每天一個分頁（名稱是日期，依查驗時間；讀不到用照片日期；都沒有放「日期未知」），A 照片（固定在該列格子）、B 照片文字；另有清單、基準、分項工程、已確認詞彙、詞庫。
- B 欄固定順序，一行一欄位：
```
查驗時間：2026-10-27（115.10.27）
照片日期：2026-10-27
查驗項目：（白板寫「檢查項目」也放這欄）
位置：
檢查人員：
查驗說明：（白板有「品名 型號 數量」等欄頭就寫在括號內，例 查驗說明（品名 規格｜實測｜數量）：）
（白板內容逐行照抄，保留分行、品名、型號、數量；表格欄用「｜」分隔；旁註寫成「（旁註：…）」）
```
- 查驗時間：民國加 1911 換西元（用程式算），括號附白板原樣；照片日期：EXIF 或浮水印；兩者不同時程式自動加「（≠查驗時間）」紅字；讀不到只寫 UNKNOWN，原因寫在回覆。
- 一律繁體；讀不清寫〔?〕（寫入時自動編號〔?1〕〔?2〕…紅字，確認過的號不重排）；不猜字、不補型號。白板整張入鏡但沒有該欄：「—（白板無此欄）」；被裁切或沒拍到：「UNKNOWN（原因）」。
- 固定欄位第一次出現的值成為基準，之後不同就略過不寫並問。

## 詞庫與名詞
- 公共工程同一物件重複多，全案寫法要一致：抄寫前看詞庫（＊＝使用者確認／型錄／匯入）、已確認詞彙、公司名詞；相同照寫，不同或型號有一碼看不清仍標〔?〕問，候選第一個放詞庫寫法。同系列型號常只差一碼（V2700／V2701 可能是不同品項），不憑詞庫補碼。
- 寫入後看「疑似同物不同寫法」；同一張白板上並列的詞（上彎／下彎、P管／S管）視為不同物件。換新檔可 `glossary 新檔.xlsx --import 詞庫.csv`；使用者確認、型錄、匯入的詞重建時保留，白板判讀但已不在任何列的詞自動移除。
- 公司給新的材料自主檢查表時，把名詞加進 forms.csv（同一張表用同一個表號）。

## 物件辨識（關鍵字＋規格）
- 使用者要求：看到「關鍵字＋規格」就要知道是哪一項物件。判斷順序：
  1. 先用型號／品號（白板的型號欄，例 U4360F、EF1014B、TOS-EA-32、YSP-606D）比對 forms.csv 的「型號」「型號規格」欄；命中就用表上的材料/設備名稱與項目。
  2. 沒有型號時，用品名關鍵字（例 面盆、閘門閥、線槽、EMT）加規格（例 25、E19、3"、10K）比對 forms.csv 的「材料/設備名稱」「項目」欄。
  3. 比對不到：照白板寫，並在回覆列為「未建檔」，請使用者確認是否新增到 forms.csv。不得自行套用近似品名。
- 已拍到但不在 forms.csv 的常見物件（例 衛生設備：面盆、掛式便斗、自動龍頭、排水器、拖布盆）：屬其他自主表，用白板內容寫入，並在回覆列出。

## 回覆格式（使用者指定，固定不變）
```
**2026-10-27｜第 1 張**｜已將「無」填入。
**查驗時間**：2026-10-27（115.10.27）
**照片日期**：2026-10-27
**請確認**：
1. 面盆型號：L331／L334？
2. 排水器最後一字：器／部？
```
- 位置用「日期｜第 N 張」（當天第 N 張＝工作檔列號 − 1）；標題粗體。第一行：新增「已新增。」、回覆後「已將「X」填入。」、只提問時只寫位置。第二、三行照抄查驗時間、照片日期。改到日期而搬到別的分頁時，寫新位置，最後一行提醒「已從 X 搬到 Y」。
- 「請確認」一題一行、附候選字（最多 3 個）；題號＝格子裡的〔?N〕＝放大圖編號；沒有就省略。
- 批次：進度只回一行「已完成 30／100 張」；結束先一行總結（寫入幾張、略過幾張、待確認幾張、材料自主檢查照片 N 頁），再接有待確認的區塊（一則最多 10 張）。分項工程名稱未填的另列「請確認」。提醒放最後一行。
- 使用者只回一個詞（例「王小明」「無」）→ 更新字形與候選最吻合的那一處；對應不到只問一行「「X」是第幾題？」。
- 不解釋判斷過程，不另起四段或流程鎖。新對話第一次交檔加一行：下次接續請上傳這次的材料自主檢查照片.xlsx。
- 另列：分項工程名稱未填、未建檔物件、棟別未填、實測未填，各列一次。

## 額度與分批（使用者指定：不縮圖）
- 不要求使用者縮圖。省額度靠分批與新對話：每批約 5 張；每批結束交出工作檔，下一批開新對話上傳該檔＋新照片。
- 同一對話中已上傳的圖會在每一輪重送，所以多輪來回是主要成本；確認問題簡短。
- 放大圖只附讀不清的字，不每張都附。
- 依照 GitHub 公開版 scripts/ 取得程式，避免重寫程式（重寫耗額度）。

## 常見錯誤
- 每個新對話重寫整份程式，耗大量額度：從 scripts/ 複製或從 GitHub 下載。
- 交兩個檔讓使用者搞混：只交材料自主檢查照片.xlsx，工作資料藏在隱藏工作表（build_company 第三參數）。
- 聊天直接上傳的照片常沒有 EXIF；zip、Drive、電腦資料夾的原檔通常有。浮水印時間不保證正確，和查驗時間不同兩個都寫，不自行判斷哪個對。
- 藍筆在灰白板、反光下對比低：先看增強圖。簡體偏旁潦草最難認（纟寫成一筆鋸齒＝縫）。小字與旁註容易漏字（漏抄「塞」）。照常用詞自動補字（把像「部」的字寫成「器」）要避免。
- 手寫型號易混：1／7、0／D、5／S、2／Z、V／1/；要和包裝盒印刷型號或官方型錄完全相同才算確定；數量和型號尾碼黏在一起（LF6450N 6）看同欄對齊再判斷。
- 沒有 LibreOffice 時跳過轉 PDF，回覆說明未做版面抽看。
- Excel 與 LibreOffice 換行位置不同：字寬估算抓寬；輸出後一定轉 PDF 抽看。
- 帶顏色的粗體在部分手機預覽不顯示：前兩行只用粗體不加顏色。
- iPhone HEIC 要 `pip install --break-system-packages pillow-heif`，裝不起來請使用者改存 JPG；手機直拍依 EXIF 轉正（prep 已處理）。
- 百張的額度：每張先看 1200 寬格線圖，只對讀不清處放大；寫入後不重看；進度存在 manifest.csv，接續時不從頭再看。
- OpenCC 會誤報：斗→鬥、台→臺；冲要看上下文（沖水的「沖」或衝擊的「衝」）。只當偵測器，不自動替換。
- 詞庫自動抓品名只取每行第一段中文，可能抓到片語（例「搭接 10cm 封固」）；只供對照，不必修。
- 改正日期後舊的「（≠查驗時間）」殘留、或含〔?〕的日期被誤標（2026-11-01 發現）：重新判斷前先拿掉舊標註，只有兩邊都是完整 YYYY-MM-DD 才比較。
- 不同天接在同一頁不好找也不好列印：每天一個分頁；查驗時間讀錯會放錯分頁，改正後自動搬頁（2026-11-02 使用者要求）。
- 照片浮在格線上會和列錯開：固定在該列格子裡（2026-11-02 使用者要求）。
- 部分手機預覽不顯示同一格內的部分粗體：使用者說看不到粗體時，先問用哪個 App 開檔。
- 公共工程同一物件寫法前後不一（例 L331／L3301）會讓查找與統計失準：抄寫前看詞庫，寫入後看「疑似同物不同寫法」。
- 同一物件在不同自主表出現不同廠牌（例 80∮閘門凡而：消防管件頁與閥類頁廠牌不同）：兩筆都保留，不自行合併，請使用者確認。
